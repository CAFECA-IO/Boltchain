# ADR 0011：AI 算力市場（算力的 Airbnb）

- 狀態：已採納（2026-09-26），實作分三期（見「分期」）

> **2026-09-26：發行分配（60/20/20）、算力份額與金絲雀任務已被 ADR 0012 取消。** `ComputeMarket` 只是單純的付費市場（委託收入、押金、爭議與驗證小組）；本文與金絲雀任務、算力份額有關的段落僅供參考。存儲抽查開放給未質押節點已依 ADR 0012 實作。
- 相關：ADR 0002（不加客製交易）、ADR 0003（發行）、ADR 0007（PoW 啟動）、ADR 0009（儲存層與抽查）
- 參考：CAFECA-IO/SwarmStorage `src/lib/file_operator.ts`（切片上傳與下載）

## 目標

Boltchain 要成為 AI 算力的 Airbnb：

- 委託者付 BOLT，請別人的機器跑 AI 推論，依消耗的 AI tokens 計價。
- 執行者提供機器，完成工作就拿到 BOLT。
- 輸入與輸出檔案放在 IPFS，先切片、加密再存；只有委託者與執行者能解讀內容。

## 情境：新加入者，有機器、沒有 BOLT

### 現在能做什麼

| 階段 | 不花錢取得 BOLT 的方法 | 限制 |
| --- | --- | --- |
| A（挖礦）、B（質押確認） | 用 CPU 挖 RandomBOLT：`wallet new` 後 `mine --beneficiary <地址>`。區塊獎勵直接記給地址，不需要先有 BOLT 付手續費 | 只用到 CPU，GPU 閒置；全網算力增加後收益下降 |
| B | 挖到 64 BOLT 後質押成為驗證者，領確認投票與抽查獎勵 | 質押、`set-peer` 要手續費（用挖到的 BOLT 付） |
| C（PoS） | **沒有**。挖礦結束，新人只能買 BOLT 或接受別人付款 | 算力市場尚不存在 |

結論：今天在階段 A 與 B，新人可以只花電費拿到 BOLT，但跟 AI 算力無關。進入 PoS 以後，這條路就關閉了。
另外，ADR 0003 說存儲抽查獎勵「不需質押、第一天對所有人開放」，實作上（M5）保存者卻是從已質押的驗證者中選出，兩者不一致。

### 要讓「用機器、不花錢拿到 BOLT」成立，必須解決的五件事

1. **零 BOLT 入門**：執行者第一次收錢之前，不能要求他付手續費。
2. **有工作可做**：市場初期委託者很少，新人也要有收入來源。
3. **不用押金也能開始**：沒有 BOLT 就付不出押金，得用「從收入中累積押金」取代。
4. **能驗證真的算了**：確認執行者真的用指定模型跑完，並且 token 數正確。
5. **加密儲存**：確保只有雙方看得到內容，檔案也要保存得夠久。

## 設計

### 1. 零 BOLT 入門：執行者不付手續費也能收錢

- 執行者只在鏈下簽名：接單、交付收據。
- 結算交易 `ComputeMarket.settle(收據)` 任何人都能送出，手續費由委託者的託管款支付：委託者自己送，或由中繼者代送，中繼者從款項抽固定的小額費用。
- 執行者的報酬直接轉入他的地址。收款不需要 gas，所以執行者從頭到尾不必持有 BOLT。
- 做法符合 ADR 0002：只用系統合約加一般交易，不新增交易類型。之後可評估 EIP-7702 代付，讓執行者也能自己送交易。

### 2. 初期工作來源：協定驗證工作（金絲雀任務）

- 發行量新增「算力」份額（比例見待決事項）。這筆份額只付給**協定發出的驗證工作**，不付給一般委託：
  - 每個 epoch 由亂數種子推導出一批提示與模型，由抽中的驗證者小組加密派發給執行者。
  - 驗證者事先算好或抽樣比對答案。對的執行者依 token 數分得當期算力份額，錯的扣信譽。
- 這批工作同時用於量測與作弊偵測：執行者分不出它和真實委託，因此用小模型充數、捏造 token 數或直接不算，都會被抓到。
- **防刷量**：不把發行量按「一般委託的付費金額」分配。否則執行者可以自己付錢給自己，用手續費換發行量。一般委託的收入就是委託者付的費用，協定不另外補貼。
- 隨真實需求成長，算力份額可以逐步縮小（寫死曲線，符合「治理只靠硬分叉」）。

### 3. 用收入累積押金，取代先付押金

- 新執行者註冊免押金（註冊交易也由中繼代送，費用從第一筆收入扣）。
- 每筆收入先扣 X% 作為押金，直到達到目標額，例如 64 BOLT，與驗證者最低質押相同。
- 押金與信譽決定接單上限：可接的單筆金額、同時進行的工作數、可跑的模型大小。新人只能接小單與金絲雀任務。
- 作弊（金絲雀答錯、爭議敗訴）沒收押金。押金可在退出冷卻期後取回。

### 4. 計量與驗證

- **token 數**：委託時指定模型的 tokenizer（以 CID 固定版本）。輸入 token 數由輸入檔決定，輸出 token 數由輸出檔決定，雙方都能獨立重算，爭議時也能由驗證小組重算。
- **結算流程（樂觀）**：
  1. 執行者交付加密的輸出與收據（輸入 CID、輸出 CID、token 數、輸出雜湊、簽名）。
  2. 委託者在 T 小時內可以接受或提出爭議；沒動作就視為接受。
  3. 任何人都能送結算交易。
- **正確性（分三層）**
  1. 金絲雀任務與信譽（第一版）。
  2. 爭議時選擇性揭露：委託者把內容金鑰加密給抽中的驗證小組，由小組重跑。LLM 在不同 GPU 上無法逐位元重現，因此比對用容忍值，例如 logits 前 k 名的一致性，而不是逐字比對。
  3. TEE 等級（之後）：支援機密運算的 GPU 附上遠端證明，只接受有證明的執行者。這一級連執行者本人也看不到明文。
- **限制要寫清楚**：沒有 TEE 時，執行者為了計算一定看得到明文。「只有委託者與執行者能解讀」在儲存與傳輸上可以做到；對執行者的信任則靠信譽、押金與 TEE。

### 5. 加密切片儲存（Boltchain Vault 格式）

**`file_operator.ts` 現況**（CAFECA-IO/SwarmStorage）：

- 沒有任何加密，分片與 metadata 都是明文。metadata 還包含檔名、MIME、原始大小與分片清單。
- Reed-Solomon 是假實作：同位分片全是 0，重建時把缺的分片補 0。任何一片遺失，檔案就會默默損壞。
- 每個 stripe 固定填到 20 MB（5 × 4 MB），小檔案（提示、短輸出）的浪費很大。
- 分片經由中心化的 `/api/v1/file` 上傳下載，不是 IPFS 點對點。

**建議格式**，實作為 Rust crate `bolt-vault`，節點與 CLI 共用，另外提供 WASM 版給瀏覽器：

1. 每個檔案產生一把隨機的 256 位元內容金鑰 K。
2. 明文先補齊到級距大小（例如 64 KiB、1 MiB、16 MiB…），只洩漏大約的大小。然後切成 1 MiB 的區塊，每塊用 XChaCha20-Poly1305 或 AES-256-GCM 加密，把區塊序號與總數放進 AAD（STREAM 結構），防止區塊被調換或截斷。
3. 對密文做真正的 Reed-Solomon（k 個資料片、m 個同位片），每片以 raw block 放進 IPFS。只要任意 k 片還在，就能還原。
4. 清單（manifest）記錄分片 CID、演算法參數與每塊的驗證標籤，同樣用 K 加密，產生清單 CID。
5. K 以 HPKE（RFC 9180，X25519）分別包給委託者與執行者的**加密公鑰**。加密金鑰與簽章金鑰分開，在 `ComputeMarket` 登記。
6. 鏈上只記錄清單 CID 與兩份包好的金鑰。檔名與型別放在加密的清單裡。

執行者要等配對後才確定，所以委託者先用 K 加密並上傳，配對後只需要把 K 包給執行者，不必重新上傳。輸出檔由執行者用新的金鑰 K′ 加密，同樣包給雙方。

**保存**：

- 委託者與執行者的節點預設釘住（pin）自己的工作檔案。
- 需要長期保存時，另開「保存委託」：延用 ADR 0009 的抽查機制，按保存期間付費。
- 到期後可以回收。抽查只驗證密文，不需要金鑰。

### 6. 工作流程

1. **註冊**：執行者用 `boltchain provider init` 偵測 GPU、跑基準測試，產生加密金鑰，簽署註冊資料；由中繼代送或自己送。
2. **委託**：委託者存入託管款（上限 = 最大 token 數 × 單價），指定模型（模型登記表的 ID）、截止時間、最低信譽。
3. **配對**：
   - 執行者在 gossip topic `/bolt/<chain>/compute` 公布報價與可用容量。
   - 委託者選定一位（或由合約依價格與信譽自動指派），執行者簽名接單。
4. **執行**：執行者下載並解密輸入。模型從 IPFS 以 CID 取得並快取，在沙箱中執行，執行期間不能對外連線。
5. **交付與結算**：見第 4 節。多出的託管款退還委託者，執行者的報酬扣除押金比例後入帳。

### 7. 模型登記表（無管理者）

- 任何人都能登記模型：權重 CID、tokenizer CID、執行環境（例如 llama.cpp 或 vLLM 的版本與容器摘要）、參數量與建議 VRAM。
- 登記表不審核，也沒有管理員。金絲雀任務只會從「有足夠執行者宣告支援」的模型中抽選。

### 8. 付款代幣

- 委託者可以付 BOLT，或付執行者接受的任何 ERC-20（例如跨鏈的穩定幣）。協定發行的算力份額一律是 BOLT。
- 委託者要取得 BOLT，可以透過 Uniswap v4 池等方式，這部分由市場決定。

## 實作紀錄：驗證小組的裁決（2026-09-26）

- 每個 epoch 起點，待處理的爭議交給從委員會抽出的驗證小組（`assignDisputes`）。
- 投票（`VerdictVote`，簽署內容以 `boltchain/verdict/v1` 開頭，與抽查的簽章分開）在 storage topic 上傳播；超過三分之二相同時聚合成 `VerdictCert`，出塊者放進 envelope 的 `audits` 清單（與抽查憑證共用，編碼互不相容，不會混淆）。
- 鏈在執行區塊前驗證：工作仍在爭議中、爭議分派給憑證的 epoch、簽署者超過小組的三分之二、聚合簽章正確；通過後系統呼叫 `recordVerdict`。收到的區塊只要有一張無效就整塊拒絕。
- 公開測試網從分叉 `swarm`（第 2401 塊）起接受裁決憑證；其他鏈從 genesis 起。

## 實作紀錄：命令列、檔案分享與判定程式（2026-09-26）

**執行者**（`boltchain provider`）

- `register`：在 `ComputeMarket` 登記，公布加密金鑰（由帳戶私鑰衍生，與 `boltchain storage` 相同）。
- `run --backend <URL> --model <id>=<名稱>`：接受指定給自己、且模型有對應的工作；經由自己的節點（`--rpc-storage`）取得並解密輸入，呼叫 OpenAI 相容的後端（llama.cpp 的 `llama-server`、Ollama、vLLM），把回應加密給委託者與自己後交付；token 數取自後端的 `usage`，並以工作的上限為界。
- `status`、`collect`（結算已過爭議窗口的工作並提領）。
- 目前執行者自己付 gas；零 BOLT 的簽名路徑（`acceptFor`、`deliverFor`）已在合約中，中繼服務尚未完成。

**委託者**（`boltchain job`）

- `post --provider <地址> --model <id> --prompt <文字>`（或 `--input` 指定 OpenAI 格式的請求）：加密給執行者與自己，交給自己的節點，第一次使用時登記自己的加密金鑰，託管最大費用。
- `status`、`result`（取回並解密，印出回答）、`approve`（核可並付款）、`dispute`、`share`、`refund`、`withdraw`。
- 目前必須指定執行者；開放給任何執行者承接（`shareInput` 流程）尚未完成。

**把爭議檔案交給驗證小組**

- 每位驗證者的節點由 BLS 金鑰衍生一把 X25519 加密金鑰，每分鐘在 storage topic 上公布（以 BLS 簽章，節點驗證後保存；RPC `bolt_verifierKeys`）。
- 小組指派後，委託者執行 `job share`：用自己的內容金鑰替輸入、輸出與理由各做一份加入小組成員為收件人的新 envelope（不必重新上傳資料），交給自己的節點，並以帳戶私鑰簽署後廣播（`DisputeShare`，RPC `bolt_shareDispute`）。節點驗證簽署者就是該工作的委託者。
- 委託者不分享，小組無法判定，爭議 7 天後判執行者勝。

**判定程式**（`boltchain judge`，給 `--verifier-cmd` 使用）

- 節點以 `sh -c` 執行判定命令，環境變數帶入工作資料、分享後的 CID、這個節點其中一個席位的加密私鑰（`BOLT_VERIFIER_KEY`）與節點的 RPC 位址。
- 判定規則（第一版）：
  1. 還沒分享、讀不到輸入或輸出：棄權，1 分鐘後重試（收到分享時立即重試）。
  2. 交付的輸出不是 JSON 或沒有回答：執行者有錯。
  3. 在自己的後端以相同請求重跑（未指定時 temperature = 0）：宣稱的輸入 token 數超過重跑的 110% + 8，或輸出 token 數超過實際回答的 110% + 8（後端有 `/tokenize` 時精確計算，否則以 4 個字元一個 token 估計）：執行者有錯。
  4. 回答與重跑結果的詞彙重疊（Jaccard）低於 `--min-similarity`（預設 0.3）：執行者有錯。
  5. 其他：執行者沒錯。
- 限制：不同 GPU、不同量化的同一模型輸出會不同；相似度門檻要依實際模型與題型調整。之後改用 logits 比對（ADR 0011 原設計）或 TEE（ADR 0013）。

**測試**：`m7_compute` 在開發鏈上跑完整流程：執行者登記、委託、以模擬後端執行與交付、委託者讀回並付款；第二筆工作被爭議，委託者分享檔案，小組成員以 `boltchain judge` 在另一個回答不同的後端重跑，判定執行者有錯，委託者拿回款項、執行者被罰押金。

## 實作紀錄：中繼、開放承接、模型登記、log-probability 判定、瀏覽器（2026-10-14）

- **中繼**：節點加 `--relay-wallet <帳戶檔> --relay-min-fee <BOLT>` 就開放 `bolt_relay`。它只代送認得的呼叫（`ComputeMarket` 的 `registerFor`、`acceptFor`、`deliverFor`、`settle`、`payout`；`EnclaveLease` 的 `checkpoint`、`activate`、`payout`），費用低於下限、或 `eth_estimateGas` 顯示會失敗的都拒絕，壞請求不花中繼的錢。執行者端 `provider register|run --relay <URL> --relay-fee <BOLT>`。
- **中繼費**：`acceptFor` 簽 `(id, fee)`、`deliverFor` 簽 `(id, output, tokensIn, tokensOut, fee)`；代送者與費用記在 `relays[id]`（上限 0.1 BOLT），結算時先從工作款項付給中繼，剩下的才給執行者；工作沒有結算（退款、裁決執行者有錯）就不付，中繼承擔與執行者相同的風險。
- **開放承接**：`job post` 不給 `--provider` 就是開放工作，輸入只加密給委託者；任何登記的執行者都能接（`provider run --open --min-price-in/out`），接單後委託者的 `job post --wait` / `job watch` 用 `add_recipient` 把執行者加為收件人並 `shareInput`。執行者發現輸入還讀不到時會稍後重試。
- **ModelRegistry**（`0xB017…0007`）：任何人登記模型（名稱、權重 CID、tokenizer、執行環境、參數量、建議 VRAM），同一組權重 / tokenizer / 執行環境不能重複登記，執行者可以宣告支援（`setSupport`）。`post` 要求模型已登記。命令列 `boltchain model register|list|support`。
- **log-probability 判定**：執行者預設要求後端回傳每個輸出 token 的 top-5 log-probability 並交付；`boltchain judge` 先檢查聲稱的 token 數不超過列出的數量、token 拼起來等於答案，再以貪婪解碼重跑，比對 top-k 重疊（預設 ≥ 0.5）、平均 log-probability 差距（≤ 1.0）與第一個分歧處的差距（`--tie-gap` 2.0，處理近乎平手的 token）。`job post --logprobs` 讓缺少 log-probability 的交付在爭議中直接判錯。
- **瀏覽器**：「AI 推論」頁列出模型、執行者（從最近 500 件工作整理）、工作與工作詳細頁。節點設定了 CAFECA 錢包時可以直接發出工作：提示在瀏覽器內以 bolt-vault（WASM，約 350 KB，`scripts/build-vault-wasm.sh`）加密給委託者在瀏覽器保存的 X25519 金鑰與指定的執行者，區塊交給節點保存（`POST /api/compute/host`），以 CAFECA 頻道送出 `setEncryptionKey`（需要時）與 `post`；結果在瀏覽器內解密（`GET /api/compute/blocks`）。網頁只能發出指定執行者的工作，開放工作要用命令列（需要監看接單）。
- **部署**：新版 `ComputeMarket` 與 `ModelRegistry` 在開發鏈與主網的 genesis；公開測試網在第 233401 塊的硬分叉 `tee` 換上（`relays` 放在儲存佈局最後，舊工作照常結算，有測試）。
- **測試**：`m7_compute`（零 BOLT 執行者經中繼登記、接開放工作、交付附 log-probability 的結果，中繼與執行者的收款）、`m7_verdict`、合約測試 `relayers_of_signed_actions_are_paid_from_the_job`、`jobs_name_a_registered_model`、`the_testnet_tee_fork_keeps_compute_state`、判定程式的單元測試。

## 分期

1. **第一期（測試網）**
   - `bolt-vault`
   - `ComputeMarket` 的託管、收據與樂觀結算
   - `provider` 與 `job` CLI，先支援 llama.cpp
   - 委託者或中繼付 gas
   - 驗收：新錢包零 BOLT 註冊，接一筆委託，拿到 BOLT
2. **第二期**
   - 金絲雀任務與算力份額
   - 從收入累積押金
   - 信譽與接單上限
   - 驗收：沒有任何委託者時，新執行者也能靠金絲雀任務累積收入；用小模型冒充會被抓到
3. **第三期**
   - 爭議時選擇性揭露與驗證小組重跑
   - 保存委託
   - TEE 等級
   - ERC-20 付款

## 決定（2026-09-26，專案負責人）

1. **發行分配**：共識 60% / 存儲 20% / 算力 20%（原本共識 80% / 存儲 20%）。取代 ADR 0003 與 ADR 0007 的分配；共識份額在階段 B 仍由礦工與委員會 60 / 40 對分。
2. **算力份額從挖礦階段（階段 A）開始**，挖礦結束前就有第二條不花錢的入門路徑。
3. **爭議由驗證小組處理**：第一期就包含爭議揭露與驗證小組重跑，不只靠金絲雀任務與信譽。
4. **存儲抽查開放給沒質押的節點**：依 ADR 0003 的原意；以從收入累積押金取代質押門檻。
5. **SwarmStorage 改用 `bolt-vault` 的 WASM 版**，兩邊共用同一種檔案格式。
